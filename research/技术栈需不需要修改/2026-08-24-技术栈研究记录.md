# 游戏技术栈研究记录

> 研究日期：2026-08-24
>
> 研究范围：评估原 3D 技术栈是否适合网页运行，并为“类似《星露谷物语》的 2D 像素风、可自由走动、单人网页游戏”确定目标技术栈。
>
> 当前结论：撤销 Godot 3D 基线，改用 Next.js + React + TypeScript + Phaser 的 Web-first 2D 架构。

## 1. 背景

项目最初的技术栈基线是：

- Godot 4.7.x；
- Typed GDScript；
- Blender 到 glTF/GLB 的 3D 素材管线；
- 以桌面构建为首发目标。

进一步明确产品需要直接在网页中运行后，原方案出现两个问题：

1. 3D 场景、模型、光照和材质会显著提高浏览器包体、加载时间和低配置设备压力；
2. Godot Web 会增加 WASM/PCK、GDScript、独立导出和 JavaScriptBridge 等第二套工程链路，与已有 Next.js/React/TypeScript 网站集成成本较高。

因此，产品方向调整为：

- 俯视 2D 像素风；
- 单人游戏；
- 玩家可以在诊所等像素场景中自由走动；
- 可以与 NPC、家具、门和检查设备交互；
- 问诊、检查、诊断、评分和复盘仍是核心玩法；
- 桌面与移动浏览器为正式运行平台。

## 2. 引擎审核结论

### Phaser 4.2.1

优点：

- 为浏览器设计，不需要额外 Web 导出层；
- 内置 Scene、Tilemap、相机、动画、输入、音频和 Arcade Physics；
- 可以直接使用 TypeScript；
- 可以和现有 Next.js/React 工程共享状态模型、测试和构建工具；
- 适合俯视像素 RPG、自由移动、NPC 交互和多场景切换。

风险：

- Phaser 4 是较新的主版本，部分文档和第三方插件仍在迁移；
- 必须精确锁定 4.2.1；
- MVP 不依赖未经验证的 Phaser 3 插件；
- 游戏体验以 WebGL 为运行前提；不承诺 Canvas 可玩降级，WebGL 不可用时由 React/DOM 显示兼容性提示。

项目属于没有 Phaser 历史包袱的新项目，因此选择当前稳定主版本 Phaser 4，而不是为兼容旧插件停留在 Phaser 3。代价是需要接受生态迁移期风险，并通过精确锁版和真实浏览器 PoC 控制升级。

结论：推荐作为游戏运行时。

### Godot 4.7.x 2D Web

优点：

- TileSet、TileMapLayer 和场景编辑器成熟；
- 桌面原生游戏制作体验强。

不适合当前项目的原因：

- Web 构建依赖 WASM、PCK 和 WebGL 2；
- 会增加包体、冷启动和移动 Safari 兼容成本；
- 需要同时维护 GDScript 与 TypeScript；
- LLM 流式接口、网页 UI 和浏览器存档需要额外桥接；
- 更适合桌面原生为主、Web 为辅的产品。

结论：技术上可行，但不作为 Web-first 项目的首选。

### PixiJS 8

优点：

- 渲染性能和灵活性较好；
- React/TypeScript 集成容易。

不适合当前项目的原因：

- PixiJS 主要是渲染引擎，不是完整游戏框架；
- 需要自行补齐 Tilemap、碰撞、Scene 生命周期、音频、相机和 RPG 内容工具链。

结论：开发量和长期维护成本高于 Phaser，不作为主运行时。

## 3. 目标技术栈与决策状态

| 层级 | 选择 | 决策状态 |
|---|---|---|
| 网页框架 | Next.js 16.x Active LTS | 已锁定大版本策略；实施时选择最新安全补丁 |
| UI | React 19 + TypeScript | 已锁定 |
| 游戏运行时 | Phaser 4.2.1 | 已锁定精确版本 |
| 渲染 | WebGL 主路径 | 已锁定 |
| 地图编辑 | Tiled 1.12.2 JSON | 已锁定文件格式与版本基线 |
| 碰撞 | Phaser Arcade Physics | 已锁定 |
| 像素素材 | Aseprite 或 LibreSprite | 未锁定编辑器；运行产物统一为 PNG 和元数据 |
| 网页样式 | CSS Modules + CSS 自定义属性 | 已锁定首版默认方案 |
| 本地存档 | IndexedDB，使用版本化存档结构 | 已锁定 |
| LLM 服务 | MVP 使用 Next Route Handlers/BFF | 已锁定首版方案 |
| 单元测试 | Vitest | 已锁定 |
| 浏览器测试 | Playwright + 移动真机 smoke test | 已锁定测试方法；目标真机型号待 PoC 前登记 |

当前工程仍是 Next.js 15、React 19 和 TypeScript 初始化壳。package.json 尚未包含 Phaser 或目标测试依赖，仓库中也尚未建立 Tiled 地图产物；这不代表开发电脑没有安装 Tiled 桌面编辑器。

## 4. 推荐运行架构

~~~text
Next / React DOM
├─ 首页、游戏外壳和加载状态
├─ 问诊、检查、诊断、设置和结果
├─ 键盘焦点与无障碍
└─ 调用同源 /api/game/*

typed event bridge
├─ Phaser -> React：NPC、交互、场景和状态事件
└─ React -> Phaser：暂停、继续、关闭、传送和设置

Phaser
├─ Tilemap、玩家和 NPC
├─ 自由移动、碰撞和交互区
├─ 相机、遮挡层和场景转移
└─ 场景内音效和轻量提示

Next 服务端
├─ LLM 调用
├─ 病例授权披露
├─ 隐藏事实、标准答案和评分规则
└─ 可选正式成绩和云存档
~~~

React 不逐帧控制 Phaser 对象。Phaser 只处理实时世界，文字密集的医疗交互使用语义化 DOM。

状态所有权遵守以下原则：

- Phaser 持有角色坐标、动画、相机和碰撞等瞬时空间状态；
- 纯 TypeScript domain 层持有任务、对话、进度和可保存的业务状态；
- React 只消费展示状态并发送命令，不直接修改 Phaser 内部对象；
- Next 服务端持有隐藏病例事实、标准答案和正式评分；
- 跨 React/Phaser 边界的命令和事件使用可序列化、带明确类型的负载；需要进入存档或 API 的结构必须单独版本化。

## 5. 地图与像素素材约束

Tiled 地图建议使用以下固定层名：

| 层 | 用途 |
|---|---|
| Ground | 可行走地面 |
| Decoration | 不参与碰撞的装饰 |
| Collision | 墙、家具和边界 |
| AbovePlayer | 树冠、门框等遮挡层 |
| Objects | 出生点、NPC、交互区和转场点 |

需要遵守：

- 每个 tileset 使用一张连续 PNG；
- 不使用 Collection of Images tileset；
- 发布地图使用未压缩 Tiled JSON；
- 首版内联 tileset 定义；
- 如果编辑阶段使用外部 .tsj，发布前必须扁平化并验证；
- 存档保存稳定的 mapId、npcId、questId 和 interactionId，不保存 Tiled GID 或 Phaser 对象；
- 逻辑分辨率和 tile 尺寸由代表性美术 PoC 决定，暂不把 320×180 或 16px 写死。

## 6. 单机存档

浏览器进度使用 IndexedDB，并包含：

- schemaVersion；
- contentBuildId；
- updatedAt；
- slotId；
- 可序列化的游戏状态。

存档需要支持版本迁移、自动保存以及 JSON 导入/导出。

本地存档只保证同一设备、同一浏览器的单机进度。隐私模式、用户清理站点数据和浏览器存储回收都可能导致数据丢失。未来需要跨设备同步时再增加服务端云存档。

## 7. LLM 与安全边界

单人游戏不等于纯前端应用。只要运行时调用 LLM，就需要服务端可信边界。

以下内容不能进入 public 目录、客户端 bundle 或 IndexedDB：

- 模型 API key；
- system prompt；
- 未向玩家披露的病例事实；
- 最终答案；
- 评分 rubric；
- 防提示注入规则。

浏览器只接收当前回合允许展示的数据。MVP 由 Next Route Handlers 处理病例、会话、检查、诊断和结果；只有独立扩缩容或 Python 医疗流水线成为明确需求时才拆分 FastAPI。

## 8. 当前项目目录说明

当前 app 目录是 Next.js App Router 的源码入口：

- app/layout.tsx：根布局、页面元数据和全局 CSS 入口；
- app/page.tsx：根路径首页，目前只是项目初始化占位页面；
- app/globals.css：全局样式和深色模式。

以下目录不是手工维护的源代码：

- node_modules：npm install 下载的第三方依赖，可以通过重新安装恢复；
- .next：Next.js 的构建输出和开发缓存，可以由 npm run dev 或 npm run build 重新生成。

node_modules 和 .next 都已在 .gitignore 中排除，不应提交或手工修改。

## 10. 推荐实施顺序

1. 将当前 Next.js 15 壳迁移到当时最新的 Next.js 16 安全补丁。
2. 精确安装 Phaser 4.2.1，建立 client-only GameCanvas 和销毁逻辑。
3. 建立 React 与 Phaser 的 typed event bridge。
4. 制作一张代表性诊室地图，验证移动、碰撞、遮挡、NPC、转场和音频解锁。
5. 在桌面 Chrome/Firefox、iOS Safari、Android Chrome 和目标低端设备上测量性能。
6. 根据 PoC 确定逻辑分辨率、tile 尺寸和素材预算。
7. 接入 React 问诊 UI、IndexedDB 存档和 Next 服务端 LLM API。
8. PoC 验收通过后再批量制作地图、角色和病例。

PoC 进入验收前必须登记目标设备和预算。最低检查项包括：

- 桌面 Chromium、Firefox、iOS Safari 和 Android Chrome 均能完成进入地图、移动、碰撞、NPC 交互和转场；
- 目标低端移动设备的首次加载时间、峰值内存和持续帧率有实测记录；
- WebGL 不可用时显示 React/DOM 兼容性说明和处理建议，不出现黑屏；
- React Strict Mode 重挂载后只有一个 Phaser 实例；
- 刷新页面后 IndexedDB 测试存档可以恢复；
- 预算未达标时不进入批量地图与美术生产。

## 11. 暂不进入首版

- 3D、Godot、GDScript、Blender 和 glTF/GLB；
- 网络多人和实时同步；
- Matter.js、ECS 和自制游戏引擎；
- 未验证的 Phaser 插件；
- PWA 离线缓存；
- Redis、任务队列和通用向量数据库；
- 把完整问诊和长文本界面放进 canvas；
- 同时维护 Phaser 和另一套游戏运行时。

## 12. 术语说明

- WASM：WebAssembly，Godot Web 构建在浏览器中运行的二进制格式。
- PCK：Godot 打包游戏资源使用的文件。
- BFF：Backend for Frontend，专门服务当前前端的同源服务端接口层。
- typed event bridge：React 与 Phaser 之间使用明确 TypeScript 类型的命令和事件通道。
- Tiled GID：Tiled 内部用于标识 tile 的全局编号，不适合作为长期存档 ID。
- PoC：Proof of Concept，正式制作内容前验证核心技术风险的代表性原型。
- smoke test：快速确认关键路径能否正常运行的冒烟测试。
- 病例授权披露：服务端只向玩家返回当前提问或检查允许公开的病例事实。
