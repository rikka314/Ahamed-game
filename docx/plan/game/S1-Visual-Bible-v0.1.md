# AhaMed Doctor Game — Visual Bible v0.1

> 状态：视觉方向 `APPROVED`（H2 已通过）；所有像素尺寸均为候选，等待 H3 真机冻结。  
> 当前技术样片：`contentBuildId=dev`，全部为 PLACEHOLDER，不是正式美术。

## 体验目标

目标玩家在第一局结束时应感到：我在一间可信、友好、节奏克制的小诊所里完成了一次清楚的接诊循环；医疗信息值得认真阅读，但空间不会像医院管理系统一样冰冷。

五个关键词：温暖、专业、清楚、克制、有人情味。

永久禁止方向：

- 不做恐怖医院、脏乱急诊、血腥或压迫式画面；
- 不以患者外貌、服饰、年龄或体型暗示诊断；
- 不混用等距视角、斜透视和正交俯视，不混用多套像素密度；
- 不复制《星露谷物语》或其他现有游戏可识别的素材、UI、角色比例、构图和色板；
- 不把长段中文、病例答案、品牌文案烘焙进 Canvas 图片；
- 不使用高饱和霓虹、拟真血液、夸张奖励爆炸、博彩式反馈或诊疗反射小游戏。

## 三个互斥方向

| 方向 | 视觉语言 | 优点 | 成本与风险 | 当前结论 |
|---|---|---|---|---|
| A 暖晨社区诊所 | 奶油墙面、鼠尾草绿、琥珀灯光、少量珊瑚提示；木质接诊桌；圆角但不过度卡通 | 与“温暖而专业”最一致；中文 DOM UI 容易保持可读 | 需要控制暖色，避免像咖啡店；像素轮廓必须足够清楚 | **已批准主方向；S2 placeholder 已用于布局样片** |
| B 静谧现代门诊 | 冷白、蓝灰、青绿色；模块化家具；更现代的医疗 UI | 医疗可信度高、信息层级直接 | 容易显得企业化、缺乏生活感；手机上浅灰层级可能不足 | 备选，不与 A 混成双主风格 |
| C 街坊旧诊所 | 暖灰、褪色木色、旧式挂钟和手写感小物；更强叙事痕迹 | 记忆点强，空间有人情味 | 资产细节量最高；年代感容易被误读为医疗落后 | 备选，仅可提取“生活痕迹”，不能与 A 同时主导 |

当前无 AhaMed 品牌规范和用户参考图。项目负责人授权 AI 从 Kenney、OpenGameArt、itch.io 等开放素材社区整理候选；每个候选仍须记录“只借鉴什么”、来源、作者、URL、下载日期和许可，不能整体临摹或因“免费”自动采用。

### 形状、光线与像素规则

- 世界采用 top-down orthographic 正交俯视；单一光线方向候选为左上至右下。
- 门、桌、座椅、电脑、帘子、床和设备必须凭轮廓即可辨识，不能依赖烘焙文字。
- 角色使用固定脚点，坐姿对齐座位锚点；患者可共享基础骨架，但肤色、发型、衣着和主色需尊重且可区分。
- 医生不固定性别、年龄或其他人物信息，以专业、平静、可亲为共同约束。
- 正式患者组参考模型层当前三种公开人物人格制作三类可区分原型；人格只影响公开形象与表达气质，不把医疗事实或诊断暗示写进外观。
- 体温检查采用无玩家操作的角色演出：医生从抽屉取出体温计并递给患者，患者完成测量后归还，医生再收回抽屉；交接动作清楚但克制，不做反射小游戏或夸张医疗表演。
- 阴影只表达接触面与前后遮挡，不做柔焦、抗锯齿或大面积渐变。
- 中文长文全部由 React DOM 渲染；Canvas 只显示场景、短状态或锚点表现。

## 第一间诊所功能布局

```text
桌面额外可见：上方未来 CT / B 超锁定区（灰雾、不可进入）

左侧室外             中部接诊区                         右侧帘后区
队列 01/02 → 门 → 患者座 ← 接诊桌/电脑/叫号 → 医生座 | 帘子 | 床/基础设备
                    固定进门路径 → 落座                 exam anchor

```

空间合同：左侧队列和门、中部接诊、右侧检查不可重选；手机横屏优先同屏看见上述关键区域，桌面可额外看见上/下锁定区。平台差异只影响构图，不影响权威状态。

## 候选技术规格（待 H3）

| 项目 | 16px 候选（当前样片） | 32px 候选 | H3 评审点 |
|---|---|---|---|
| 世界网格 | 26×16 tiles；源地图 416×256；tile 16×16 | 同一功能布局放大到 832×512；tile 32×32 | 手机是否仍能同屏覆盖队列/门/接诊区；资产工作量 |
| 逻辑视口 | 320×180 候选，CSS 响应式放大；桌面 zoom 0.82、touch zoom 1；移动镜头中心左移到 x=188 以容纳两名队列患者 | 640×360 候选或更紧镜头 | 中文气泡锚定、像素清晰度、遮挡与安全区 |
| 角色 frame | 候选 16×24；程序占位实际尺寸不冻结 | 候选 32×48 | 坐姿可读性、脚点和动作帧成本 |
| pivot / foot point | 候选 `(0.5, 1.0)`；脚部碰撞体窄于角色宽度 | 同比例 | 桌椅绕行与座位对齐 |
| 动画命名 | `idle-{n,s,e,w}`、`walk-{n,s,e,w}`、`sit-{direction}` 候选 | 相同 | H3 后冻结帧序和 FPS |

当前 16px 样片已提供桌面和 Pixel 7 横屏模拟截图，但 32px 原生资产样片与真机数据尚未取得，所以 H3 保持 pending。不要把浏览器 CSS 放大当作 32px 原生资产证据。

## UI 与可访问性

- 页面与运行条使用深森林背景；主要操作以琥珀色焦点和高对比文字表达。
- 电脑、叫号、触控方向键、灰盒离场操作均提供真实 DOM button 与可访问名称。
- 电脑面板是模态对话框；打开时暂停 Phaser 世界输入，关闭后恢复。
- coarse-pointer 竖屏显示可访问旋转对话框并暂停世界；恢复横屏不重复提交流程命令。
- coarse-pointer 横屏把操作与方向键叠放在 stage 安全区，并限制 stage 高度；真实视口测试要求 Canvas 与方向键同时在屏内。
- 气泡为 DOM，跟随稳定屏幕锚点；中文不烘焙进像素图。
- 保留 `prefers-reduced-motion` 分支；焦点状态不能只靠颜色。

## 声音方向

MVP 同时制作 SFX 与 BGM，正式音频由项目负责人制作/提供，AI 负责规格、转换、集成和验收。SFX 至少覆盖门铃、电脑确认、叫号、脚步、坐下、帘子、抽屉开关、体温计交接、患者普通/愤怒离场、金币、声望、购买、升级、解锁和错误。BGM 暂时只制作 1 首可无缝循环的诊所日间主题，不制作独立标题/菜单曲。音频应温暖、克制、无喜剧化医疗设备声；首次用户手势后再解锁 Web Audio。
