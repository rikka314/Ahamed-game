# Web 2D 像素单人游戏技术栈基线

> 用途：作为 apps/game/ 的技术选型、工程结构和实施边界。目标是在桌面与移动浏览器运行单人 2D 像素游戏，玩家可在多个场景自由走动、与 NPC 和环境交互，并进入问诊、检查、诊断和结果流程。
>
> 决策日期：2026-08-24
>
> 当前状态：工程仍是 Next.js 15 初始化壳；本文描述正式开发前应迁移到的目标基线，不代表依赖和玩法代码已经落地。

> 分层定位：本文是三层架构中的**游戏层基线**。模型层见 `开源资源与技术方案.md`；两层之间的 DTO、状态机、API、版本和合并门槛见 `共享层基本内容.md`。前期游戏层代码放在项目根 `game/`，不得直接依赖 `model/` 内部实现。

## 1. 审核结论

采用：

~~~text
Next.js 16.x + React 19 + TypeScript
└─ client-only Phaser 4.2.1
   ├─ Tiled 1.12.2 JSON 地图
   ├─ Arcade Physics 碰撞
   ├─ WebGL 主渲染路径
   ├─ 键盘 / 鼠标 / 触摸输入
   └─ IndexedDB 本地单机存档
~~~

Next.js 继续作为网页壳和服务端 BFF；Phaser 只负责实时游戏世界。React/DOM 负责对话、问诊表单、菜单、设置、存档提示和结果页。LLM 密钥、病例隐藏事实、标准答案和评分规则只存在于服务端。

原 3D Godot 基线撤销。浏览器是正式主平台，项目又已经采用 React/TypeScript，因此继续使用 Godot 会引入 GDScript、WASM/PCK、独立导出和 JavaScriptBridge 等第二套链路。对当前 2D 玩法而言，这些成本没有对应收益。

## 2. 引擎横向评估

| 候选 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| Phaser 4.2.1 | 浏览器原生；Scene、Tilemap、Arcade Physics、相机、动画、输入和音频内置；与 Next/TypeScript 共用工具链 | Phaser 4 是较新的主版本，文档和第三方插件生态仍在迁移 | 推荐，精确锁定版本 |
| Godot 4.7.x 2D Web | 2D 场景与 TileSet 编辑器成熟，桌面原生导出能力强 | Web 依赖 WASM/WebGL 2；包体、冷启动、Safari/移动 Web、流式 API 桥接和双测试体系成本更高 | 仅当未来以桌面原生为主平台时重评 |
| PixiJS 8 | 轻量、灵活的高性能渲染层 | 不是完整游戏引擎；需要自行拼装地图、碰撞、Scene、音频和内容工具链 | 不作为本项目主运行时 |

选择 Phaser 是综合工程决策，不表示它在每一项指标上都最强。它最适合“现有 Next 项目 + 浏览器首发 + 俯视像素场景 + 中小型单人游戏”这一组约束。

## 3. 核心技术栈

| 层级 | 目标选择 | 用途与约束 |
|---|---|---|
| 网页框架 | Next.js 16.x Active LTS | App Router、页面外壳、同源 API、部署；进入玩法开发前从当前 Next 15 迁移到当时最新安全补丁 |
| UI | React 19 + TypeScript | 对话、菜单、设置、结果、加载和无障碍界面；不逐帧驱动游戏对象 |
| 游戏运行时 | Phaser 4.2.1 | 精确锁版；client-only 加载；MVP 不依赖未验证的 Phaser 3 插件 |
| 渲染 | WebGL 主路径 | Phaser 4 的 Canvas 路径已弃用；AUTO 可保留有限降级，但完整体验以 WebGL 为验收目标 |
| 地图 | Tiled 1.12.2 JSON | 场景、碰撞、出生点、NPC、交互区和转场点的数据来源 |
| 物理 | Phaser Arcade Physics | 俯视移动、矩形碰撞、overlap 和 Tilemap collider；不引入 Matter.js |
| 像素素材 | Aseprite 或 LibreSprite | 编辑源文件；运行时只发布 PNG spritesheet/atlas 和元数据 |
| 网页样式 | CSS Modules + CSS 自定义属性 | 延续当前项目，不为首版强制增加 Tailwind |
| 本地存档 | IndexedDB + idb | 异步本地存档、版本升级、导入导出；正式成绩和隐藏数据不以客户端存档为准 |
| 服务端 | Next Route Handlers/BFF | LLM、病例授权披露、评分、可选账号和云存档；有明确 Python 独立扩缩容需求时再拆 FastAPI |
| 测试 | Vitest + Playwright | 纯 TypeScript 规则单测；真实浏览器输入、Canvas、DOM 和 IndexedDB 端到端测试 |
| 版本控制 | Git；大素材按需 Git LFS | 可编辑源素材与网页运行产物分离，第三方素材建立许可证台账 |

本机 npm 默认 registry 当前可能无法及时解析 Phaser 4.2.1。实施安装时必须确认官方 npm registry 的版本并精确锁定，不使用浮动 latest。

## 4. 运行时边界

~~~text
浏览器
├─ Next / React DOM
│  ├─ 页面、加载与错误边界
│  ├─ 对话、问诊、检查、诊断、设置与结果
│  ├─ 可访问性与键盘焦点
│  └─ 调用同源 /api/game/*
├─ typed event bridge
│  ├─ world -> UI：交互区、NPC、场景、加载和状态事件
│  └─ UI -> world：继续、关闭、暂停、传送和配置命令
└─ Phaser
   ├─ 世界场景、Tilemap 与遮挡层
   ├─ 玩家、NPC、动画与相机
   ├─ 碰撞、触发区与场景切换
   └─ 场景内音效和轻量 HUD

模型层可信服务端（MVP 可由 Next Route Handlers 承载）
├─ 病例与会话授权
├─ LLM 调用和流式响应
├─ 隐藏事实、答案、rubric 与模型密钥
└─ 可选的正式成绩、账号和云存档
~~~

上图描述最终运行数据流，不表示模型实现归游戏层所有。前期 `game/` 只通过 `share/` 契约和 mock adapter 开发；真实病例、LLM 和评分实现位于独立 `model/` 边界。合并 MVP 时可以同进程部署，但仍禁止游戏代码直接读取模型层内部数据。

### 4.1 React 与 Phaser 的所有权

- Phaser 只在 Client Component 中动态加载，禁止 SSR 执行 Phaser 模块。
- GameCanvas 在 useEffect 中创建唯一 Phaser.Game，卸载时必须 destroy(true)。
- React Strict Mode 会在开发环境额外执行 setup/cleanup；初始化必须可重入，不能留下第二个 canvas、事件监听器或音频实例。
- React 不同步每帧坐标。跨边界只传稳定业务事件和可序列化数据。
- 文字密集、表单、弹窗和关键操作使用语义化 DOM，不把核心医疗交互全部画进 canvas。

### 4.2 游戏内部职责

~~~text
BootScene       最小启动资源、能力检测、错误提示
PreloadScene    当前章节资源、加载进度、失败重试
WorldScene      地图、玩家、NPC、碰撞、相机、交互区
OverlayScene    仅用于场景内轻量提示，不承载复杂问诊表单

domain/
├─ player       位置、朝向、移动许可
├─ interaction  稳定交互 ID 与触发规则
├─ dialogue     对话/问诊状态机，不依赖 Phaser Scene
├─ case         浏览器允许看到的病例投影
├─ progression  任务、解锁和时间
└─ save         可序列化存档与迁移
~~~

世界状态、任务、病例投影和存档结构保持为纯 TypeScript。Scene 负责适配渲染和输入，不能成为业务数据的唯一保存位置。

## 5. 像素世界与地图规范

### 5.1 逻辑分辨率

- 使用固定逻辑分辨率 + Phaser Scale FIT + CENTER_BOTH。
- 开启 pixelArt 和 roundPixels；相机 startFollow 后显式保持 roundPixels。
- tile 尺寸、角色帧尺寸和逻辑分辨率由首张美术 PoC 一起确定。320×180 + 16px tile 可作为候选，但在美术验收前不写成不可变合同。
- 游戏世界坐标、相机和关键 UI 锚点尽量保持整数，避免像素抖动。
- CSS 容器必须提供可计算尺寸；横竖屏不改变世界坐标语义。

### 5.2 Tiled 层级合同

~~~text
Ground          可行走地面
Decoration      不碰撞装饰
Collision       墙、家具和场景边界
AbovePlayer     树冠、门框等玩家上方遮挡
Objects         出生点、NPC、交互区、门和转场点
~~~

推荐对象属性：

| 属性 | 用途 |
|---|---|
| id / interactionId | 稳定交互标识 |
| npcId | NPC 内容映射 |
| spawnId | 出生点 |
| targetMap / targetSpawn | 场景转移 |
| caseContextId | 映射当前病例上下文，不包含隐藏答案 |

不要在存档中保存 Tiled GID、数组下标或 Phaser 对象；只保存稳定的 mapId、npcId、questId 和 interactionId。

### 5.3 Phaser/Tiled 兼容约束

- 运行时导出使用 Tiled JSON。
- 每个 tileset 使用一张连续 PNG；不使用 Collection of Images tileset。
- 首版地图内联 tileset 定义。若作者阶段使用外部 .tsj，构建阶段必须验证并扁平化后再发布，因为 Phaser 当前解析器不直接支持 external tileset source。
- 不启用压缩 tile data；发布 JSON 使用解析器已验证的未压缩数据。
- 真实 PoC 必须覆盖 tile layer、object layer、自定义属性、碰撞和场景转移，不能只验证静态地图。
- Aseprite packed atlas 元数据不能默认视为 Phaser-ready；先用固定网格 spritesheet，确需 atlas 时增加可测试的转换步骤。

## 6. 移动、碰撞与交互

- 桌面默认 WASD / 方向键移动，E、Enter 或点击交互。
- 移动端提供 pointer 交互和虚拟方向键，不假设存在键盘。
- 使用 Arcade Physics；玩家碰撞体缩到脚部矩形，使角色头部可以视觉上穿过遮挡。
- 墙体和家具碰撞来自 Collision 层；NPC 和交互点使用 overlap 或距离检测。
- 进入交互时暂停玩家移动，关闭后恢复；DOM 弹窗打开时必须防止按键继续传入世界。
- 不使用复杂刚体模拟。移动速度、对角线归一化、场景入口和交互优先级写成可单测规则。

## 7. 素材生产与加载

### 7.1 源文件和运行产物

~~~text
assets/source/
├─ maps/          Tiled .tmj/.tsj 源文件
├─ sprites/       .aseprite 或其他可编辑源文件
├─ tilesets/      原始像素素材
└─ audio/         可编辑音频源

public/game-assets/<content-build-id>/
├─ maps/          运行时 JSON
├─ tilesets/      PNG
├─ sprites/       spritesheet/atlas
├─ audio/         浏览器格式
└─ manifest.json  资源版本与校验信息
~~~

- build ID 路径视为不可变；更新内容时发布新路径，避免地图和脚本版本错配。
- Boot 只加载进入画面、玩家、公共 UI 和首张地图；其他场景按章节预加载。
- 为加载失败提供重试和可读错误，不以黑屏或无限加载作为降级。
- 优先 sprite sheet/atlas 和复用 tileset；在真实 profile 前不做猜测式对象池和压缩优化。
- 首发不以 PWA/service worker 为前置条件。先做好普通网页缓存、版本化资源、刷新读档和更新提示；出现明确离线需求后再评估 PWA。

### 7.2 音频

- 第一次明确的点击/触摸后再创建或恢复音频上下文。
- 提供静音、音乐和音效音量控制，并把设置写入本地存储。
- 音频资源按场景分组；转场和销毁时清理循环播放。

## 8. 单人存档

浏览器本地存档使用 IndexedDB。idb 只作为小型 Promise/TypeScript 包装层，不引入完整数据库框架。

~~~ts
type SaveEnvelope = {
  schemaVersion: number;
  contentBuildId: string;
  updatedAt: string;
  slotId: "autosave" | string;
  payload: GameSave;
};
~~~

规则：

- IndexedDB database version 负责 object store/index 结构；schemaVersion 独立负责游戏内容迁移。
- 迁移函数按 v1 -> v2 -> v3 串联、幂等并测试；写入前保留旧值或备份。
- 关键进度自动保存，并提供 JSON 导出/导入，避免浏览器清理导致唯一存档丢失。
- 可以在形成有效进度后请求 navigator.storage.persist()，但返回 false 时游戏必须正常工作。
- 隐私模式、用户清理站点数据和浏览器存储回收都可能删除本地存档；产品界面必须说明“同设备、同浏览器”的边界。
- 如果以后需要跨设备同步，增加服务端云存档；不要把本地 IndexedDB 误当成账号数据或防作弊来源。

### 8.1 模拟经营领域

模拟经营规则属于游戏层的纯 TypeScript domain，不放入 Phaser Scene，也不交由 LLM 决定。建议至少拆成：

~~~text
domain/
├─ economy       货币、收入、支出和交易流水
├─ inventory     设备、消耗品和容量
├─ facilities    房间、设备位、购买、升级和维修
├─ reputation    声望、等级和解锁条件
├─ quests        主线、支线、每日目标和完成条件
├─ calendar      游戏内日期、时段和时间推进
├─ rewards       医学评分到游戏奖励的版本化换算
└─ progression   场景、NPC、病例类型和功能解锁
~~~

每项规则必须可序列化、可单测并能在没有 Phaser 的情况下运行。Phaser 只把规则结果表现为动画、数值变化和场景变化。

共享层只向游戏层提供医学评分等稳定输入；具体经验、金钱、声望和解锁由游戏层计算。模型输出的自然语言不得直接作为奖励计算依据。尚未确定的经济曲线、设备价格、任务数量、时间速度和奖励公式保留为待审核内容，不在技术 PoC 中提前写死。

## 9. LLM 与数据安全边界

单人不等于纯前端。只要运行时调用 LLM，就需要服务端可信边界。

- 模型 API key、system prompt、隐藏病例事实、最终答案、评分 rubric 和防提示注入规则只放在模型层可信服务端；MVP 可以由 Next Route Handlers 承载该服务端边界。
- Phaser/React 只接收当前回合允许披露的患者事实和展示数据。
- 浏览器 public/、source map、客户端 bundle 和本地存档中不得出现答案或未披露事实。
- 会话、检查、诊断和结果统一通过 /api/game/* 同源接口；流式文本优先使用标准 Fetch/SSE。
- 业务稳定前由 Next Route Handlers 直接编排；只有独立扩缩容、Python 医疗流水线或离线批处理成为明确需求时才拆 FastAPI。
- 正式评分、每日挑战或排行榜必须由服务端计算和记录；本地存档只提供单机进度体验。

## 10. 测试与发布门槛

### 10.1 Vitest

- 地图对象和自定义属性解析。
- 移动、对角线速度和交互优先级。
- 对话、任务、病例披露和诊断状态机。
- 存档序列化、round-trip、旧版本迁移和损坏数据。
- 随机规则显式注入 seed。

### 10.2 Playwright

- Client-only Phaser 初始化和 React Strict Mode 重挂载。
- 真实键盘、鼠标、触摸与虚拟方向键。
- 地图加载、碰撞、交互区、转场和暂停恢复。
- React DOM 对话与 canvas 的焦点隔离。
- IndexedDB 写入、刷新恢复、迁移和导入导出。
- 资源失败、WebGL 不可用和音频未解锁提示。

浏览器矩阵至少覆盖：

- 桌面 Chromium 与 Firefox。
- WebKit 自动化 smoke。
- iOS Safari 与 Android Chrome 真机 smoke。
- 一个低端移动设备档位的首屏加载、内存和持续帧率。

移动端模拟不能替代真机。视觉回归只固定少量稳定场景，不把跨操作系统字体和 WebGL 像素差异当作功能错误。

### 10.3 发布验收

- 完整玩法在 WebGL 下可用；无 WebGL 时显示明确兼容性提示，Canvas 只作 best-effort 降级。
- 首张代表性地图可稳定达到目标帧率；预算由 PoC 在目标设备上测量后写入。
- 首包、单地图贴图内存、音频和切场加载设可观测预算。
- 所有静态资源都有 content build ID；旧存档和新内容的兼容结果可预测。
- 依赖升级前运行真实地图、存档和三类浏览器 smoke test。

## 12. 许可证策略

- Phaser 为 MIT；Tiled 编辑器自身为 GPL，但其导出地图和用户素材不因使用编辑器自动变成 GPL。
- Aseprite 制作的游戏素材可商用，但团队按其 EULA 为实际使用者配置许可，不能随项目再分发编辑器。
- LibreSprite 可作为免费替代，但其编辑器许可证和导出兼容性仍需单独核对。
- 默认接受 MIT、Apache-2.0、BSD 和 CC0；CC BY 必须完成署名。
- 默认避免 CC BY-NC、来源不明、只写“免费”或不允许改编/商用的素材。
- 每个外部代码和素材记录作者、URL、版本/下载日期、许可证、修改情况和使用位置。

## 13. 不进入首发基线

- Godot、GDScript、Blender、glTF/GLB 和 Godot Web export。
- 3D、动态光影、复杂 shader 和大规模粒子。
- Matter.js、ECS、自制游戏引擎和未经验证的第三方 Phaser 插件。
- 网络多人、实时同步和 authoritative multiplayer server。
- PWA 离线缓存、通用向量数据库、Redis 和任务队列。
- 把完整问诊 UI、设置、结果或长文本放进 canvas。
- 把隐藏病例、答案、评分规则或模型密钥打包到浏览器。
- 同时维护 Phaser 与另一套游戏运行时。

## 14. 实施顺序

1. 审核当前根目录 Next 15 壳是迁入 `game/` 还是保留为最终集成壳；决定后再迁到当时最新的 Next 16 安全补丁。
2. 精确安装 Phaser 4.2.1，建立 client-only GameCanvas、销毁逻辑和 typed event bridge。
3. 用一张代表性诊室地图完成技术 PoC：自由移动、碰撞、遮挡、NPC、交互、转场、响应式缩放和音频解锁。
4. 在桌面 Chrome/Firefox、iOS Safari、Android Chrome 和目标低端设备上测首包、内存与 FPS；据此锁定逻辑分辨率和 tile 尺寸。
5. 依据 `share/` contract v1 创建模型 mock adapter，把问诊、检查、诊断和结果做成 React DOM，与 Phaser 世界事件连接。
6. 建立最小模拟经营闭环：一次诊疗评分能够转换为一种奖励，并解锁一种设备或内容。
7. 建立 IndexedDB 存档、schema migration、导入导出和内容 build ID。
8. 通过共享 fixture 和契约测试后接入真实模型 API，验证隐藏事实不会进入客户端。
9. 合并门槛通过后扩展地图、病例和内容；最后再评估 PWA、账号和云存档。

PoC 通过门槛后才批量生产地图和美术，避免在分辨率、Tiled 导出合同或移动端性能未经验证时返工。

## 15. 决策摘要

~~~text
Platform:       Web-first, desktop + mobile browser
Web shell:      Next.js 16.x + React 19 + TypeScript
Game runtime:   Phaser 4.2.1, client-only
Renderer:       WebGL required for full experience
World:          Tiled 1.12.2 JSON + Arcade Physics
Art:            Aseprite/LibreSprite -> PNG spritesheets
UI:             React DOM + CSS Modules/custom properties
Persistence:    IndexedDB + versioned SaveEnvelope + import/export
Integration:    share contract v1 + mock adapter + versioned model API
Testing:        Vitest + Playwright + mobile real-device smoke
Scope:          Single-player 2D pixel free-roaming game
~~~
